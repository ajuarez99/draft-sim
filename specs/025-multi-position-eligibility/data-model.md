# Data model: Multi-position eligibility (spec 025)

There is **no schema change and no migration.** `player.positions` (text[]) already holds every eligible position, in Sleeper's alphabetical order.

## Wire: `SimulationResult.PlayerRef` (Java) / `PlayerRef` (TS)

| Field | Type | Status |
|---|---|---|
| `position` | string | **unchanged.** Still the alphabetical-first position. Kept for older clients and the out-of-scope pages; draft-room labels stop presenting it as primary. |
| `positions` | `string[]` (Java `List<String>`, never null; TS `positions?: string[]`) | **new.** Every eligible position, in stored order. Empty only for a player with no stored positions, who falls back to `[position]` on the client. |
| `positionalRank` | int | **unchanged on the wire.** The draft room hides it for multi-position NBA players (research R3). |

The record has two construction sites, `PlayerRef.from(BoardEntry)` and `LeagueController.fallbackPlayerRef`. Both fill `positions` from `player.positions()`. `api.ts` mirrors the field in the same change (constitution rule 2).

## Client-side derived values (not stored)

- **`eligiblePositions(p)`**: `p.positions` if present and non-empty, else `[p.position]`. This is the single fallback rule.
- **`positionLabel(p, sport)`**: for NBA, the eligible positions joined with "/" in the order PG, SG, SF, PF, C. For football, the stored order.
- **`posRank(p)`**: unchanged for single-position players. For multi-position NBA players it is just `positionLabel`, with no number.
- **Scarcity pool[pos]**: the count of top-S board players with `pos ∈ eligiblePositions(p)`. "Left" subtracts drafted players from every pool they were in.
- **Lineup**: the TS port of `BasketballRules.prepareLineup` (matroid greedy plus Kuhn), which returns the filled slots and a can-join answer for a candidate. It is pinned to the backend by the parity fixture `web/src/__fixtures__/nba-lineup-parity.json`.

## Parity fixture: `web/src/__fixtures__/nba-lineup-parity.json`

Generated by a backend test from `BasketballRules`. The backend test fails when the committed file is stale.

```json
{ "template": ["PG","SG","G","SF","PF","F","C","UTIL","UTIL"],
  "cases": [ { "name": "...", "players": [ { "id": 1, "positions": ["PG","SG"], "adp": 12.0 } ],
               "seated": [1, 4], "filledByKind": { "PG": 1, "G": 1 },
               "canJoinByMask": [true, true, false, ...] } ] }
```

`canJoinByMask` is indexed by the five-bit mask over (PG=1, SG=2, SF=4, PF=8, C=16), the same bit order as `BasketballRules.POSITION_BIT`.
